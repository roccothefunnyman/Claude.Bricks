Overview

This walkthrough takes you through every step of executing Scenario 2, from extracting structural features from .ldr files to deploying a trained anomaly detection model behind a managed online endpoint. Each step shows the exact commands to run and what to expect.

Scenario 2 trains an Isolation Forest (unsupervised anomaly detection) on structural features extracted from .ldr files. It identifies buildings with unusual structural properties (high overhang, collisions, extreme height-to-base ratios). Deployed as a managed online endpoint that returns pass/fail predictions.

Step 3: Feature Engineering

3

Extract Structural Features from .ldr Files

Parse LDraw files and compute 4 structural metrics per building

The feature engineering script parses each .ldr file in the input directory and extracts four numeric features that characterize the structural properties of the building.

Terminal
cd deploymentcode/scripts/scenario2 python feature_engineering.py \ --input-path ../../data/scenario2/ldr-files/ \ --output-path features.csv \ --label-file labels.csv # Output: features.csv with filename + 4 features + optional label column
Label file is optional
The --label-file argument is only needed if you plan to use the supervised random_forest model type in Step 5. For the default Isolation Forest (unsupervised), labels are not required.

Extracted Features

FeatureFormulaWhat It Detects
overhang_ratio unsupported parts / total parts Parts floating without support below them. High values indicate structurally unstable designs.
collision_count parts at exact same (x, y, z) position Parts clipping through each other. Any value above 0 suggests modeling errors.
height_to_base_ratio height range / sqrt(footprint area) Extremely tall, narrow buildings that would topple in real life.
layer_density variance of parts-per-layer distribution Uneven layer distribution. High variance means some layers are dense while others are nearly empty.

Sample Output

CSV
# features.csv filename,overhang_ratio,collision_count,height_to_base_ratio,layer_density building_001.ldr,0.03,0,1.24,0.15 building_002.ldr,0.45,12,3.87,2.41 building_003.ldr,0.01,0,0.98,0.08
Anomalous example
In the sample above, building_002.ldr has a high overhang ratio (0.45), 12 collisions, and an extreme height-to-base ratio (3.87). The Isolation Forest would flag this as a structural anomaly.

Step 8: Test the Endpoint

8

Test the Deployed Endpoint

Send test requests and verify pass/fail predictions

Test the endpoint using the smoke test script or by invoking it directly with the AML SDK.

Using smoke_test.py

Terminal
python smoke_test.py --endpoint-name ldr-validator-endpoint --num-requests 5 # Expected output: # Request 1/5: 200 OK, latency 198ms, prediction: pass # Request 2/5: 200 OK, latency 156ms, prediction: fail # ... # Results: 5/5 successful (100%), P95 latency: 210ms

Invoke Manually

Python
# Using the AML SDK from azure.ai.ml import MLClient from azure.identity import DefaultAzureCredential import json ml_client = MLClient(DefaultAzureCredential(), subscription_id, resource_group, workspace) # Normal building (should return "pass") request = json.dumps({ "overhang_ratio": 0.03, "collision_count": 0, "height_to_base_ratio": 1.24, "layer_density": 0.15 }) result = ml_client.online_endpoints.invoke( endpoint_name="ldr-validator-endpoint", request_file="sample-request.json" ) print(json.loads(result)) # {"prediction": "pass"}
Python
# Anomalous building (should return "fail") request = json.dumps({ "overhang_ratio": 0.65, "collision_count": 18, "height_to_base_ratio": 5.2, "layer_density": 3.8 }) # {"prediction": "fail"}
Interpreting Results
A "pass" prediction means the building's structural features are within normal ranges. A "fail" prediction means the Isolation Forest detected the building as an anomaly, with one or more features outside the learned distribution.

Troubleshooting

ProblemCauseFix
EnvironmentNotFound when submitting job Step 2 was skipped Run python register_envs.py --version 1
DataNotFound: ldr-validation-features:1 Data asset not registered or features not generated Run Step 3 (feature_engineering.py) then Step 4 (prepare_data.py)
Job stuck in Preparing for 10+ minutes First run builds the Docker environment image Wait. First build takes 5-10 minutes. Subsequent runs reuse the cached image.
No .ldr files found Input path does not contain .ldr files Check the --input-path directory structure. Files must have the .ldr extension.
All predictions return "pass" Contamination parameter too low for the dataset Increase contamination in train.py, or switch to --model-type random_forest with labeled data for better control.
Endpoint deployment fails with quota error Insufficient vCPU quota for DS3_v2 in your region Request a quota increase in Azure portal (Subscriptions > Usage + quotas) or use a smaller VM size
Smoke test returns 401 Unauthorized DefaultAzureCredential not picking up your identity Run az login again, or check that your identity has the AzureML Data Scientist role on the workspace
