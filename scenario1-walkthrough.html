Scenario 1: Facade Classification

Step-by-step execution guide

Random Forest • Azure ML SDK v2 • Blue/Green Deployment • Drift Monitoring

Overview

This walkthrough takes you through every step of executing Scenario 1, from setting up your local environment to deploying a trained model behind a managed online endpoint with blue/green traffic control. Each step shows the exact commands to run and what to expect.

Scenario 1 trains a Random Forest classifier on rendered facade images to categorize architectural styles (historic, modern, industrial, commercial, residential). Images are flattened to 64x64 RGB feature vectors (12,288 features) and classified using scikit-learn, with MLflow tracking and a managed online endpoint for real-time inference.

Monitor the Job

Terminal

The job typically takes 3-8 minutes depending on dataset size. The cpu-cluster scales from 0 to 1 node (cold start adds ~2 minutes on first run).

Quality Gate
In the CI/CD pipeline (train.yml), the job's test_accuracy metric is compared against a threshold of 0.85. If the model does not meet this threshold, the pipeline stops and the model is not registered. When running manually, check the metric yourself in MLflow before proceeding.

Step 8: Blue/Green Canary Rollout

8

Canary Deployment with Traffic Shifting

Safely roll out a new model version using blue/green deployment

When you retrain and register a new model version (e.g., facade-classifier:2), deploy it as a canary alongside the existing blue deployment. Gradually shift traffic to validate before full promotion.

8a. Deploy Canary (0% Traffic)

Terminal
python deploy_canary.py \ --model-name facade-classifier \ --model-version 2 \ --endpoint-name facade-classifier-endpoint \ --deployment-name green # Creates green deployment with 0% traffic # Blue retains 100% traffic

8b. Smoke Test the Canary

Terminal
python smoke_test.py \ --endpoint-name facade-classifier-endpoint \ --deployment-name green \ --num-requests 5

8c. Shift Traffic Progressively

Traffic Shifting Strategy

Green 0%

→
Blue 90%

→
Blue 50%

Blue 0%

Promoted
Terminal
# Shift 10% to green python promote_deployment.py --endpoint-name facade-classifier-endpoint --deployment-name green --traffic 10 # Monitor health for 5 minutes, then shift to 50% python promote_deployment.py --endpoint-name facade-classifier-endpoint --deployment-name green --traffic 50 # If healthy, promote to 100% python promote_deployment.py --endpoint-name facade-classifier-endpoint --deployment-name green --traffic 100

8d. Rollback (If Needed)

If the canary shows issues at any point, revert all traffic to blue and optionally delete the failed deployment:

Terminal
python rollback_deployment.py \ --endpoint-name facade-classifier-endpoint \ --target-deployment blue \ --delete-failed # Restores 100% traffic to blue # Deletes the green deployment
Rollback is instant
Traffic shifting is a metadata operation on the endpoint. No new infrastructure is created or destroyed. Rollback takes effect in seconds.

Step 9: Drift Monitoring

9

Set Up Drift Detection

Create a baseline from training data and monitor for distribution shift

Over time, the distribution of inference data may drift from the training data. This step creates a statistical baseline from your training data and compares future inference data against it.

9a. Create Baseline Profile

Terminal
cd monitoring/drift python create_baseline.py \ --training-data ../../deploymentcode/data/scenario1/features.csv \ --output baseline_profile.json # Creates baseline_profile.json with per-feature statistics: # mean, std, percentiles, histograms for each numeric feature

9b. Run Drift Detection

Terminal
python detect_drift.py \ --baseline baseline_profile.json \ --inference-data recent_inference_data.csv \ --psi-warning 0.2 \ --psi-critical 0.4 # Output: drift_report.json # Exit code: 0=none, 1=warning, 2=critical

Automated Weekly Checks

The drift-check.yml GitHub Actions workflow runs every Sunday at midnight UTC. If the overall PSI exceeds 0.3, it automatically triggers the training pipeline via repository_dispatch, retraining the model on fresh data.

Troubleshooting

Job fails with No module named 'sklearn' Wrong environment version or environment not built Check that claudebricks-sklearn:1 exists in AML Studio > Environments
Endpoint deployment fails with quota error Insufficient vCPU quota for DS3_v2 in your region Request a quota increase in Azure portal (Subscriptions > Usage + quotas) or use a smaller VM size
Smoke test returns 401 Unauthorized DefaultAzureCredential not picking up your identity Run az login again, or check that your identity has the AzureML Data Scientist role on the workspace
UserError: name already in use on compute A previous failed provisioning left a ghost resource Delete the stuck compute in AML Studio > Compute, or use a different name
