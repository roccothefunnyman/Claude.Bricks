Scenario 3: Pattern Extraction

Unsupervised clustering of LEGO construction patterns using KMeans and HDBSCAN

KMeans • HDBSCAN • Azure ML SDK v2 • Feature Extraction • Batch Analysis

Overview

This walkthrough takes you through every step of executing Scenario 3, from preparing reference .ldr files to discovering construction pattern clusters. Unlike Scenario 1, there is no endpoint deployment here. Scenario 3 is a batch/offline analysis pipeline.

Scenario 3 analyzes reference .ldr files to discover recurring construction patterns. It extracts part-usage statistics (brick counts, plate counts, slope counts, window counts, door counts, dimensions, window-to-wall ratio) and clusters buildings with similar profiles. Two paths are available: a single-step job (pre-extracted features) or a two-step pipeline (extract + cluster).

Each .ldr file is parsed for type-1 lines. Parts are categorized by part number, and dimensions are converted from LDU (1 stud = 20 LDU horizontal, 1 brick = 24 LDU vertical).

Extracted Features

FeatureDescriptionSource
total_partsTotal number of type-1 lines in the fileCount of all parts
brick_countNumber of brick parts3001, 3002, 3003, 3004, 3005, 3008, 3009, 3010, etc.
plate_countNumber of plate parts3020, 3023, 3024, 3034, 3035, etc.
slope_countNumber of slope parts3037, 3039, 3040b, 85984, 92946, etc.
window_countNumber of window parts60594, 60592, 60603, 3853, etc.
door_countNumber of door parts60596, 57895, 57896, etc.
height_studsBuilding height in brick units(Y_max - Y_min) / 24 LDU
width_studsBuilding width in stud units(X_max - X_min) / 20 LDU
depth_studsBuilding depth in stud units(Z_max - Z_min) / 20 LDU
window_to_wall_ratioProportion of window parts relative to all facade partswindow_count / (brick_count + window_count + door_count)
Dimension conversion
LDraw coordinates use LDU (LDraw Units). Horizontal: 1 stud = 20 LDU. Vertical: 1 brick = 24 LDU. The Y-axis is inverted (positive Y = downward), so height is computed as (Y_max - Y_min) / 24.

Step 8: Analyze Results

8

Analyze Cluster Results

Review cluster assignments and understand pattern archetypes

Scenario 3 is a batch/offline analysis pipeline. There is no endpoint deployment. Instead, review the cluster_assignments.csv output to understand the discovered building pattern archetypes.

No endpoint deployment
Unlike Scenario 1, Scenario 3 does not deploy to a managed online endpoint. The output is a CSV file with cluster assignments and a registered MLflow model that can be used for future batch predictions.

What Each Cluster Represents

Each cluster groups buildings with similar construction profiles. Use the cluster centroids (mean feature values per cluster) to understand what defines each pattern archetype. For example:

ClusterPossible ArchetypeDefining Features
0Standard ResidentialModerate brick count, low slope count, few windows

Troubleshooting

ProblemCauseFix
EnvironmentNotFound when submitting job Step 2 was skipped Run python register_envs.py --version 1
DataNotFound: reference-models:1 Data asset not registered or data not uploaded Run python prepare_data.py (Step 3)
No .ldr files parsed (0 rows in stats.csv) Files do not contain type-1 lines (part placements) Check that .ldr files have valid 1 <color> <x> <y> <z> ... <part.dat> lines
silhouette_score is NaN Too few buildings or all assigned to the same cluster Add more .ldr files to the data directory. Need at least 2 clusters with 2+ members each.
HDBSCAN labels all points as noise (-1) Not enough data density, or min_cluster_size too high Increase the number of buildings or decrease min_cluster_size (minimum 2)
Job stuck in Preparing for 10+ minutes First run builds the Docker environment image Wait. First build takes 5-10 minutes. Subsequent runs reuse the cached image.
Job fails with No module named 'hdbscan' Wrong environment version or environment not built Check that claudebricks-clustering:1 exists in AML Studio > Environments
UserError: name already in use on compute A previous failed provisioning left a ghost resource Delete the stuck compute in AML Studio > Compute, or use a different name
